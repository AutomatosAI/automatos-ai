The Notification Bell UI is a centralized frontend component for the **Unified Notification System (PRD-128)**. It provides real-time awareness of platform events through 30-second unread-count polling, a scrollable popover of recent notifications, and deep-linking to the relevant entities (missions, tasks, heartbeats, etc.) based on the event's `link_type`.

## Architecture & Data Flow

The UI operates by interacting with the `notifications` and `notification_preferences` tables through the FastAPI backend. Notifications are generated by the `NotificationDispatcher` service when events occur in the orchestrator or agent runtimes.

## Key Components

### 1. NotificationBell React Component
The primary entry point located in the navigation bar. It manages the following state and behaviors:
*   **Unread Count Polling:** Polls the `/api/notifications/unread-count` endpoint every 30 seconds to update the red badge count `[docs/PRDS/128-UNIFIED-NOTIFICATION-SYSTEM.md:15-19]()`.
*   **Recent Notifications Popover:** On click, fetches the 20 most recent notifications via `GET /api/notifications?limit=20` `[docs/PRDS/128-UNIFIED-NOTIFICATION-SYSTEM.md:144-145]()`.
*   **Action Handling:**
    *   **Mark Read:** Triggered when a notification row is clicked, calling `POST /api/notifications/{id}/read` `[docs/PRDS/128-UNIFIED-NOTIFICATION-SYSTEM.md:133-134]()`.
    *   **Mark All Read:** A bulk action in the popover header calling `POST /api/notifications/read-all`.
    *   **Dismiss:** An "x" button on each row that calls `POST /api/notifications/{id}/dismiss` to remove it from the view by setting `dismissed_at` `[orchestrator/alembic/versions/prd128_notifications.py:70-70]()`.

### 2. Navigation Logic (`linkFor`)
The UI uses a mapping function to resolve the `link_type` and `link_id` stored in the database into a frontend route:

| link_type | Target Route | Description |
| :--- | :--- | :--- |
| `mission` | `/missions/{link_id}` | Navigates to the Mission Detail Page |
| `task` | `/board?task={link_id}` | Opens the task on the Kanban board |
| `heartbeat` | `/agents/{agent_id}/heartbeats/{link_id}` | Shows specific heartbeat analysis |
| `playbook` | `/playbooks/history/{link_id}` | Navigates to execution logs |
| `report` | `/outputs/reports/{link_id}` | Opens the generated report |
| `file` | `/workspace/explorer?path={link_id}` | Links to a specific workspace file |

Sources: `docs/PRDS/128-UNIFIED-NOTIFICATION-SYSTEM.md:115-123`(), `docs/PRDS/129-WORKSPACE-OUTPUTS-HUB.md:9-10`()

### 3. NotificationsSettingsTab
Located at `/settings/notifications`, this component allows users to manage their delivery preferences.
*   **Bulk Editor:** Uses `GET /api/notification-preferences` to retrieve a merged list of workspace defaults and user-specific overrides `[docs/PRDS/128-UNIFIED-NOTIFICATION-SYSTEM.md:54-56]()`.
*   **Upsert Logic:** When preferences are changed, it performs a bulk `PUT` to the preferences API, which updates rows in the `notification_preferences` table `[orchestrator/alembic/versions/prd128_notifications.py:32-42]()`.

## Implementation Details

### Backend API Support
The UI is backed by the notifications and preferences endpoints. The schema supports fanning out a single event to multiple destinations (e.g., `in_app` and `telegram`) `[orchestrator/alembic/versions/prd128_notifications.py:5-9]()`.

### Scoping and Security
Every query initiated by the UI is strictly scoped to the current workspace and user. The database uses composite indices to ensure performant retrieval of unread notifications for a specific user:
`CREATE INDEX ix_notifications_unread_ws ON notifications (workspace_id, created_at DESC) WHERE read_at IS NULL AND dismissed_at IS NULL;` `[orchestrator/alembic/versions/prd128_notifications.py:84-87]()`.

### Event Types Handled in UI
The UI renders distinct icons and formatting for the 9 core event types:
1.  `heartbeat_complete`
2.  `task_complete`
3.  `mission_step_complete` (Default: Silent)
4.  `mission_complete`
5.  `playbook_step_complete` (Default: Silent)
6.  `playbook_complete`
7.  `trigger_fired`
8.  `report_submitted`
9.  `agent_error`
