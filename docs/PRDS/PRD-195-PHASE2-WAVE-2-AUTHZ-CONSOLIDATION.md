## Overview

The auth-identity dossier's headline: **authentication is solved, authorization is the module's unfinished work.** The identity + tenant-resolution spine (`get_request_context_hybrid`, `core/auth/hybrid.py:653`) is the strongest file in the module — race-safe provisioning, real cross-tenant guards, audience-pinned JWT — and it backs **91 of the 104 router modules under `api/`** on every request. But the *authorization* bolted on top forks **five ways**: five disconnected role vocabularies that do not map onto each other, no single function that answers "may principal P do action A," and the flagship per-tenant roles (`editor`/`viewer`) enforced at exactly **one router** — `api/team.py`'s six member-management endpoints. Every other mutating route accepts any authenticated member regardless of role: **a workspace `viewer` can create agents, launch Missions, edit documents, and delete deliverables** (`auth-identity` C.2). The empty-permission fork (F042) is live behaviour — an SDK key minted with no permissions is a **god-key** on the internet-facing widget plane (`ApiKeyService.check_permissions`, `core/services/api_key_service.py:234-243`: "empty … means **all** permissions") and a null-key on the board plane (`_sdk_key_has_scope`, `core/auth/hybrid.py:527-539`: empty grants **nothing**) — two opposite security semantics for the same key population. And `super_admin` is 403'd by all 8 admin routers on a default deployment (F043), because plane-OFF `caller_is_admin` returns `role == "admin"` (`core/auth/roles.py:45`).

The dossier's verdict (§E.2) is the cheap kind of fix: **the coherent model is ~80% written and dark.** `modules/policy/roles.py` already carries the `super_admin ⊇ admin ⊇ user` hierarchy (`:28-46`) and the empty-= -deny `has_permission` (`:63-77`), tested — it just only fires when `AUTOMATOS_POLICY_PLANE` is ON, and the flag defaults false (`config.py:665`) and is set in **no** deploy surface (verified: nothing in `envs/`, `docker-compose.yml`, `railway.json`). This PRD is a **consolidation, not an invention** (CLAUDE.md §3: refactor type — pick the canonical path, migrate the others, delete the losers): make `modules/policy/roles.py` the one authority, sweep a workspace-permission gate across the unguarded mutating routers, collapse the five vocabularies to one with typed adapters, and deny credentials with `workspace_id IS NULL`. Buying an FGA engine *before* this collapse would add a sixth vocabulary, not remove five (§E.5 — external FGA stays behind the T3 eval, per the dossier, and is not in this PRD).

Judged against the **North Star** — *agents acting autonomously on behalf of a scoped principal* — this is the wave that gives the platform a single enforced answer to "what may this principal do *within* its tenant." The resolution layer already knows *which tenant*; after this PRD the authorization layer can finally say *what within it* — for humans (a viewer stops being a functional editor), for keys (no more god-key-by-omission), and for the admin plane (the highest-privilege principal can reach the surfaces built for it). No new capability, no moat framing: the deliverable is that roles the product already renders **mean what they say**.

**PILOT lens (locked):** prod is **21 workspaces / 22 users** (≈1.05 users per workspace, `auth-identity` C) — the multi-seat apparatus (invitations, member roles, editor/viewer) is essentially unexercised, and that is precisely why this lands **now**: viewer-write-denial changes behaviour for approximately nobody today (solo owners pass every gate), so the blast radius is near zero, and it must be enforced *before* real multi-seat teams arrive, not after. The empty tables are cold-start, not defects; the defects are the wiring facts verified above (decorative roles, forked empty-semantics, locked-out super_admin) — see `feedback-pilot-usage-not-quality-signal`.

**Boundary with P2-11 and the do-not-touch lines (read before building):**
- **`get_request_context_hybrid` is not modified.** The in-tree design record (`core/auth/hybrid.py:~516-526`) says why: the shared dependency backs ~96 routers / 657 call sites (live grep today: **674 `Depends(get_request_context_hybrid)` sites**), and a change there alters every endpoint at once — PRD-09 deliberately built board SDK access as a *narrow, scope-gated sibling dependency* (`require_task_context`, `hybrid.py:624`) instead of touching it. This PRD follows that precedent: every new gate is an **additive per-route dependency layered after** the hybrid dep. The board plane's SDK lane and `core/auth/scopes.py` are untouched.
- **P2-11 owns the governance legs** of `AUTOMATOS_POLICY_PLANE` (budget admission, act-vs-ask, fail-closed-for-destructive at `unified_executor.py`, the four bypass lanes). **This PRD owns the role/permission legs** that today ride the same flag (F042 empty=deny, F043 hierarchy) — S1 decouples them from the mega-flag so authZ correctness does not wait on the governance rollout (posture = Gerard's call G2).
- **The PRD-143 obs tier stays super-admin-locked** (13 routers behind `require_super_admin`, enumerated by `tests/test_prd143_boundary_sweep.py`), and **PRD-185 S12's `require_workspace_admin`** gates stay. The sweep classifies these routers as already-gated; it does not relax or re-gate them.
