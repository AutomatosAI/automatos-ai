**Version:** 1.0

## Executive Summary

This master document defines a **unified widget architecture** for Automatos AI that serves dual purposes:

1. **Internal**: Power the Chatbot Workspace with a canvas-based artifact system
2. **External**: Enable embeddable widgets for customer websites and applications

The architecture follows a "Build Once, Deploy Everywhere" philosophy where the same widget components work inside the Automatos workspace AND can be packaged for external embedding via script tags or npm packages.

### The Vision: "Widgets as Universal Interface"

> **Today**: Chatbot shows results in modal overlays, one at a time
> **Tomorrow**: Canvas workspace with persistent, arrangeable widgets
> **Future**: Same widgets embedded on customer sites, connected to their Automatos workspaces

### Current State → Target State

| Aspect | Current | Phase 1 | Phase 4+ |
|--------|---------|---------|----------|
| **Artifact Display** | Modal overlay | Canvas workspace | Canvas + External embed |
| **Artifact Types** | 4 (code, text, sheet, image) | 10 types | 12+ types |
| **Layout** | Single artifact | Multi-artifact grid | Drag-drop + embeddable |
| **Persistence** | Session only | Workspace saved | Cross-platform sync |
| **External Use** | None | None | Script tag + SDK |

### Widget Component Model

All widgets share a common interface and lifecycle, enabling consistent behavior across internal and external use.

```typescript
// packages/widget-core/types.ts

/**
 * Base props that ALL widgets receive

interface WidgetBaseProps<TData = unknown> {
  // Identity
  id: string
  type: WidgetType

  // Content
  title: string
  data: TData

  // Metadata
  metadata: WidgetMetadata

  // State
  isActive?: boolean
  isLoading?: boolean
  error?: WidgetError | null

  // Layout (for canvas mode)
  position?: WidgetPosition
  size?: WidgetSize

  // Actions
  onClose?: () => void
  onMaximize?: () => void
  onMinimize?: () => void
  onRefresh?: () => void
  onAction?: (action: WidgetAction) => void

/**

 */
interface WidgetMetadata {
  source: WidgetSource
  createdAt: Date
  updatedAt?: Date
  conversationId?: string
  toolCallId?: string
  workspaceId?: string

  // For external widgets
  tenantId?: string

}

/**
 * Source information for the widget
 */
interface WidgetSource {
  type: 'tool' | 'user' | 'system' | 'workflow'
  name: string           // Tool name or action that created it
  provider?: string      // e.g., 'rag', 'nl2sql', 'composio'
}

/**
 * All supported widget types
 */
type WidgetType =
  // Phase 1 (migrate existing)
  | 'code'        // Code viewer/editor

  | 'email'       // Email viewer/composer

  | 'workflow'    // Workflow status/control
  | 'memory'      // Memory inspector
  | 'file'        // File preview/download
```

### Tool-to-Widget Mapping

The system automatically routes tool results to appropriate widgets:

```typescript
// packages/widget-core/router.ts

const TOOL_WIDGET_MAP: Record<string, WidgetType> = {
  // RAG Tools → Document Widget
  'search_knowledge': 'document',
  'semantic_search': 'document',
  'search_documents': 'document',

  // NL2SQL Tools → Data Widget
  'smart_query_database': 'data',
  'query_database': 'data',
  'execute_sql': 'data',

  // CodeGraph Tools → Code Widget
  'search_codebase': 'code',
  'get_code_context': 'code',
  'analyze_code': 'code',

  // Image Tools → Image Widget
  'generate_image': 'image',
  'edit_image': 'image',
  'analyze_image': 'image',

  // Email Tools → Email Widget
  'GMAIL_SEND_EMAIL': 'email',
  'GMAIL_LIST_EMAILS': 'email',
  'OUTLOOK_SEND_EMAIL': 'email',

  // Shell Tools → Terminal Widget
  'execute_command': 'terminal',
  'run_script': 'terminal',

  // Workflow Tools → Workflow Widget
  'run_workflow': 'workflow',
  'get_workflow_status': 'workflow',

  // File Tools → File Widget
  'read_file': 'file',
  'write_file': 'file',
  'list_files': 'file',
}

function routeToolResultToWidget(
  toolName: string,
  result: ToolResult
): WidgetType | null {
  // Explicit mapping
  if (TOOL_WIDGET_MAP[toolName]) {
    return TOOL_WIDGET_MAP[toolName]
  }

  // Infer from result structure
  if (result.database_results) return 'data'
  if (result.documents) return 'document'
  if (result.code_snippets) return 'code'
  if (result.images) return 'image'

  // No silent default - warn and return null for explicit handling
  console.warn(
    `[Widget Router] Unknown tool result format. Tool: "${toolName}", ` +
    `Result keys: ${Object.keys(result).join(', ')}. ` +
    `Add mapping to TOOL_WIDGET_MAP or update inference logic.`
  )
  return null
}

// Caller must handle null return
function handleToolResult(toolName: string, result: ToolResult) {
  const widgetType = routeToolResultToWidget(toolName, result)

  if (widgetType === null) {
    // Option 1: Show user-facing message
    showToast({
      type: 'info',
      message: `Tool "${toolName}" completed but no widget available to display results.`
    })

    // Option 2: Log for debugging and continue
    logger.info('Tool result not rendered as widget', { toolName, resultKeys: Object.keys(result) })
    return
  }

  // Create widget with valid type
  workspaceStore.addWidget(transformToolResultToWidget(widgetType, toolName, result))
}
```

## Risk Mitigation

| Risk | Impact | Mitigation |
|------|--------|------------|
| Performance degradation with many widgets | High | Virtualization, lazy loading, web workers |
| Breaking existing chat UX | High | Feature flags, A/B testing, gradual rollout |

### Risk Mitigation Details

#### R1: Performance Degradation with Many Widgets

**Trigger Threshold:** >20 widgets in canvas, or >100 widgets in workspace store

**Implementation Approach:**
```typescript
// Virtualization strategy
const VIRTUALIZATION_THRESHOLD = 20

// Use react-window for list virtualization when widget count exceeds threshold
import { FixedSizeList } from 'react-window'

function WidgetTray({ widgets }) {
  if (widgets.length > VIRTUALIZATION_THRESHOLD) {
    return (
      <FixedSizeList
        height={80}
        width="100%"
        itemCount={widgets.length}
        itemSize={160}
      >
        {({ index, style }) => (
          <WidgetThumbnail widget={widgets[index]} style={style} />
        )}
      </FixedSizeList>
    )
  }
  return <StandardWidgetList widgets={widgets} />
}

// Lazy-load widget bundles beyond initial visible widgets
const INITIAL_LOAD_COUNT = 6
const lazyWidgets = widgets.slice(INITIAL_LOAD_COUNT).map(w => ({
  ...w,
  component: lazy(() => import(`./widgets/${w.type}`))
}))

// Offload heavy processing to web workers
const chartWorker = new Worker('/workers/chart-processor.js')

function processChartData(data: ChartData): Promise<ProcessedChart> {
  return new Promise((resolve, reject) => {
    const timeout = setTimeout(() => {
      // Fallback to main-thread with throttling
      chartWorker.terminate()
      resolve(processChartDataSync(data, { throttle: true }))
    }, 5000)

    chartWorker.onmessage = (e) => {
      clearTimeout(timeout)
      resolve(e.data)
    }
    chartWorker.postMessage(data)
  })
}
```

**Implemented In:** PRD-38.1 Section 3.1 (Canvas Component), PRD-38.3 (Dashboard Builder)

#### R2: Breaking Existing Chat UX

**Trigger Threshold:** Any Phase 1 deployment

**Implementation Approach:**
- Feature flag `ENABLE_CANVAS_WORKSPACE` defaults to `false`
- A/B test with 10% of users before full rollout
- Gradual rollout: 10% → 25% → 50% → 100% over 2 weeks
- Rollback mechanism via feature flag toggle (< 5 minute recovery)

**Implemented In:** PRD-38.1 Section 9 (Rollout Plan)

#### R3: SDK Bundle Size Too Large

**Trigger Threshold:** Any widget bundle >50KB gzipped

**Implementation Approach:**
- Tree-shaking via ES modules and `sideEffects: false`
- Code splitting: each widget in separate chunk
- Lazy loading: `Automatos.widgets.chat()` loads chat chunk on demand
- Monitor with bundlesize CI check

**Implemented In:** PRD-38.4 Section 6 (CDN & Distribution)

#### R5: State Sync Complexity (Elevated to High)

**Rationale for High Impact:** State synchronization affects every widget interaction, workspace persistence, and real-time collaboration. Bugs here cause data loss and poor UX.

**Trigger Threshold:** Any multi-widget or persistence scenario

**Implementation Approach:**

```typescript
// Sync Strategy: Optimistic Updates with Conflict Resolution

interface SyncState {
  localVersion: number
  serverVersion: number
  pendingChanges: Change[]
  conflictResolution: 'client-wins' | 'server-wins' | 'merge'
}

// 1. Optimistic Updates
function updateWidget(id: string, updates: Partial<Widget>) {
  const change: Change = {
    id: generateChangeId(),
    widgetId: id,
    updates,
    timestamp: Date.now(),
    status: 'pending'
  }

  // Apply immediately to local state
  set((state) => ({
    widgets: { ...state.widgets, [id]: { ...state.widgets[id], ...updates } },
    pendingChanges: [...state.pendingChanges, change]
  }))

  // Sync to server (non-blocking)
  syncToServer(change).catch((error) => {
    // Rollback on failure
    rollbackChange(change.id)
    notifyUser('Failed to save changes. Retrying...')
  })
}

// 2. Conflict Resolution Rules
const CONFLICT_RULES = {
  // Widget position/size: Last-write-wins (most recent timestamp)
  'position': 'last-write-wins',
  'size': 'last-write-wins',

  // Widget content: Merge if possible, else prompt user
  'data': 'merge-or-prompt',

  // Widget deletion: Delete wins (prevent zombie widgets)
  'deleted': 'delete-wins',
}

// 3. Offline Support and Fallback
const offlineStore = {
  // Queue changes when offline
  queueChange: (change: Change) => {
    const queue = JSON.parse(localStorage.getItem('offline-queue') || '[]')
    queue.push(change)
    localStorage.setItem('offline-queue', JSON.stringify(queue))
  },

  // Sync when back online
  syncOnReconnect: async () => {
    const queue = JSON.parse(localStorage.getItem('offline-queue') || '[]')
    for (const change of queue) {
      await syncToServer(change)
    }
    localStorage.removeItem('offline-queue')
  }
}

// Listen for online/offline events
window.addEventListener('online', offlineStore.syncOnReconnect)
```
