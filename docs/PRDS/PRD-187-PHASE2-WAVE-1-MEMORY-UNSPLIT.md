## Overview

The memory dossier's finding is blunt: **the durable tier is dead, and has been silently, for weeks.** `MEM0_API_URL` points at a Railway hostname that answers edge-404 on every path — the deployment no longer exists — and because the client "skips silently" when unreachable and every caller catches-and-returns-empty, *Auto has been running without durable memory and nothing on any dashboard said so* (`memory.md` §C.1). Underneath that, three more loops are broken: the write side floods L2 with **~87% duplicated operational chatter** (`memory.md` §C.2, quantified from prod: 1,937 of 2,211 rows), semantic recall **cannot match by construction** (L2 recall is an `ILIKE` substring scan gated behind a temporal regex — `memory.md` §C.3), and L2→L3 promotion is **mathematically unreachable** (an `importance>0.7 AND access_count>3` gate over a population that averages 0.40–0.60 importance and whose access-count can only climb through a recall path that never fires — a bootstrap deadlock, §C.3).

The dossier's verdict (`memory.md` §E, §J.1–J.4; thesis-T2 §4) is unusually clean: **un-split.** The mem0-fork-as-a-service is the platform's one cautionary experiment in pulling an in-house capability out of the monolith — it produced a silent multi-week outage, fork-merge version debt (the auth/metadata fixes live only on an un-merged branch, §C.1), an HTTP hop with 3–5 s timeouts, and a circuit-breaker apparatus to nurse it — and it delivered *no offsetting value*, because every platform write passes `infer=False`, making the fork "a thin HTTP vector store" over someone else's server (`memory.md` §C.4, §D). The platform already runs its own Qdrant in-process for field memory (`AsyncQdrantClient(url=config.QDRANT_URL)`, `modules/context/adapters/vector_field.py:81`). The un-split reuses *that* store for a durable collection behind the existing `UnifiedMemoryService` seam, and retires the fork, the HTTP hop, and the breaker in one move.

Judged against the **North Star** — *does this make Auto more autonomously capable and the agents' output higher-quality for clients?* — this is the wave that converts memory from **subtracting** from autonomy to **functional**. Today the substrate spends tokens writing memories that nobody (human or agent) ever reads (`memory.md` §C.7 close). The four fixes here — a live in-process durable store (J1), a write side that stops flooding (J2), semantic always-on recall (J3), and a promotion path that can actually fire (J4) — are the fortnight that makes "yesterday's work makes today's work better" true again. **No moat framing; no new capability.** The deliverable is that when real traffic arrives, memory records the right things, recalls what matters, and durably keeps it.

**PILOT lens (locked):** the "87%-junk ratio," "0 promotions ever," and "6 recalls lifetime" are **real quality findings from prod code paths** (the ratio is caused by an un-gated double-writer; the 0 promotions are the mathematically-forced output of an unreachable gate) — they are architecture/wiring defects, **not** cold-start emptiness, and they are **not** scoped to "fix by driving usage." What is in scope is the *wiring*: a live store, a recall path that can match, a promotion gate that can fire, and a write path that de-dupes. See `feedback-pilot-usage-not-quality-signal`.

**Boundary with PRD-185 (already merged — do not redo):** Wave 0 S11 already shipped the **assembly-side** guard (`modules/memory/injection_filter.py` — `filter_injectable_memories` re-asserts the relevance floor over the merged candidate set and excludes `heartbeat_log`/`playbook_summary` types) **and** already removed the heartbeat write-side noise (the fabricated `User:/Assistant:` conversation and the double-write are gone — the daily digest is now a plain `logger.info`, `heartbeat_service.py:1070-1080`). This PRD's write-side story (S2) therefore scopes **only the remaining un-gated writer: the playbook double-writer.** S11's `filter_injectable_memories` is the pre-built chokepoint this PRD's semantic-L2 story (S3) plugs its new source into — its docstring already anticipates "any future L2."

## Success metrics (the definition of "un-split and functional")

- **Durable tier is live in-process** — zero `MEM0_*` config, zero `Mem0Client`, zero HTTP hop, zero circuit-breaker in the memory tree; a fact written to L3 is retrievable from the Qdrant durable collection (S1).
- **The playbook write side de-dupes** — the same recurring failure is **one memory with a count**, not N rows/run; L2's duplicated-chatter ratio can fall from ~87% as real traffic flows (the *wiring* that makes that possible, not a usage target) (S2).
- **L2 recall is semantic and fires every turn** — a non-temporal query returns relevant rows (today: 0 by construction), scored by the existing stack, floor-guarded by PRD-185 S11 (S3).
- **L2→L3 promotion can fire** — a high-importance distilled fact promotes without the impossible `access_count>3` gate; noise still doesn't promote (S4).
- **The relics are gone** — `AdvancedMemoryManager`, `MemoryKnowledgeSystem`, the empty tables, and the fake-success delete are deleted; no dangling imports (S5).
