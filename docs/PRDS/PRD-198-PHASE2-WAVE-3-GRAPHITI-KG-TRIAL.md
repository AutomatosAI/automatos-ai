## 1. What this is

A **time-boxed, eval-gated trial** of Graphiti (Zep, Apache-2.0) on the **one** Knowledge-Graph leg that genuinely lacks the machinery it needs: the document / agent-output extraction core. That leg has no entity resolution (three spellings of "Acme" are three nodes), no temporal model (a contradicted fact and its successor coexist forever), and a term-overlap-plus-BFS query that returns a neighbourhood dump instead of an answer. Those three gaps are exactly Graphiti's core, shipped and proven in OSS. This PRD does **not** adopt Graphiti — it specs the trial that decides whether to: freeze the repaired-hybrid retrieval baseline, run Graphiti on the doc leg behind a default-OFF flag, and A/B it against that baseline on the T3 eval. If it wins by the stated margin, the follow-through is the adopt path (delete-what-you-replace); if it doesn't, the flag stays OFF and the in-house fallback becomes a *new*, then-justified PRD. Either way the output is a **number**, not a bet.

**Framing (CLAUDE.md §3):** this is a **Net-new trial** — but a disciplined one. Per §11 ("new is a privilege earned by ruling out reuse"), the reuse ruling is already done: the missing capabilities are Apache-2.0 in Graphiti, so the net-new work is *integration + measurement*, not reinventing entity-resolution or bi-temporal invalidation. Adopt-not-build is the whole point.

**Build size:** the **trial** is M–L (one graph-store container + `graphiti-core` + a projection seam + the A/B harness); the **full adopt** it might unlock is L and is **out of this PRD by design** (it is the verdict's consequence, surfaced in §8, not a settled deferral). · **Risk:** High but **bounded by the gate** — a new infra dependency and higher extraction spend on the highest-traffic read path, all held behind a default-OFF flag and a projection that keeps the existing UI/tools live, so a failed trial costs the trial budget and nothing in production.

**Why now / why measured:** Wave 1 built the two things that make this trial decidable — the repaired hybrid retrieval stack (PRD-188: BM25 + Cohere rerank on pgvector) and the eval harnesses (PRD-185 S10 memory-recall, PRD-188 S5 retrieval-recall). Before Wave 1 there was no baseline to beat and no instrument to measure with; now there is. This is the cleanest eval-gated bet in the wave: it either beats a frozen number or it doesn't, and the platform already has the "capability stays dark until it beats the eval" pattern shipped (the `TOOL_ROUTING_GRAPH` read-side, held OFF until it beats `operating_graph_uplift`).

## 2. Current reality (grounded, not the review's July snapshot)

- **The doc/agent-output KG leg is a per-workspace NetworkX graph built from one-LLM-call-per-document extraction.** `modules/knowledge/graph_service.py` — `build_graph:232` collects sources (`_collect_sources:820`, **hard-capped at 8,000 chars/doc**, `:842`), extracts via `modules/knowledge/graph_extraction.py`, folds them through `build_from_json:290`, clusters, and exports. Artifacts persist as JSON blobs in the `workspace_graphs` table via `core/graph_storage.py` `DbWorkspaceClient:41` (composite key `(workspace_id, path)`; graph.json / meta.json / communities.json / latest_diff.json). This is real and maintained (the dossier found 155 fresh blobs), so the trial has organic data to run against.
- **Entity resolution is one line, and it's the wrong one.** `_merge_extractions:1048` dedups **by node id only, last-write-wins** (`:1060`). No alias sets, no embedding-similarity merge, no disambiguation. This is knowledge-graphs **C.2** — "where graph quality lives or dies," absent.
- **There is no temporal axis at all.** The incremental path is **add-only** — `add_node:1434` / `add_edge:1440`; the only `invalidate_cache:387` is an LRU cache clear, not fact invalidation. No `valid_from`/`valid_to`/`invalid_at` exists anywhere in `modules/knowledge/` (grep-confirmed empty). A contradicted fact never supersedes its predecessor. This is knowledge-graphs **C.3**.
- **The query is a neighbourhood dump.** `modules/tools/discovery/handlers_graph.py:98` `handle_query_graph` scores nodes by graphify term-overlap, BFS-traverses from the single top node, and returns a token-budgeted text dump — no embedding-seeded matching, no hybrid, no answer synthesis. Six `platform_graph_*` tools sit on it (`modules/tools/discovery/actions_graph.py`: query/neighbors/path/communities/impact/stats). This is knowledge-graphs **C.9**.
- **The episode sources the trial would feed off already funnel through one seam.** `services/knowledge_flywheel.py:124` `ingest_agent_output` (the single opt-out-gated choke point) and document ingest (`modules/rag/ingestion/manager.py:1224-1226`) both call `schedule_incremental_update:497` — the exact pendings that would become Graphiti episodes per workspace, `group_id = workspace_id`.
- **The "repaired hybrid baseline" this trial must beat is PRD-188, live on pgvector.** `modules/rag/` — `service.py` (`RAGService.retrieve`), `bm25_leg.py` (sparse leg), `fusion.py` (`hybrid_rrf`), Cohere rerank, `retrieval_filters.py`; dimension read from the `vector_store_dimensions` system setting (`modules/rag/config.py:13,96`). Documents live on `document_chunks` (pgvector, ~19k chunks, dim 2048). **This is the control.** The trial does not touch it.
- **The eval instruments exist — but the live baseline is not yet frozen.** `evals/retrieval_recall.py` (PRD-188 S5, `RETRIEVAL_RECALL_AT_5_TARGET=0.70`; variants dense/BM25/`hybrid_rrf`; the `--live --workspace <id>` run that drives real `RAGService.retrieve` "is never part of CI") and `evals/memory_recall.py` (PRD-185 S10, `RECALL_AT_5_TARGET=0.70`, whose own header says the retriever is "not yet good enough to trust as the T1-decision baseline"). Gold sets are bundled (`scripts/eval/{retrieval_recall,memory_recall}/gold_set.jsonl` + `corpus.jsonl`); the CI lanes (`retrieval-recall-eval`, `memory-recall-eval` in `.github/workflows/test.yml`) are **non-required, informational, exit-0 — the number is the deliverable, a low number is an honest outcome, not a red build**. `evals/operating_graph_uplift.py` (PRD-177 S6) is the honest **treatment-minus-baseline** A/B shape (`best_baseline`, `uplift_points`, exit-0) this trial reuses verbatim.
- **Nothing Graphiti ships today.** `graphiti-core`, `falkordb`, `neo4j`, `kuzu` are absent from `requirements.txt` and the codebase (the only `group_id` hits are Signal/LINE chat IDs, `channels/*_adapter.py`). Confirmed genuine net-new.

## 4. Stories (test-first; CI is the only gate — no local runs)

### S1 · Freeze the baseline + wire the Graphiti-vs-baseline A/B gate — S · _knowledge-graphs J8 / thesis-T1 §7_
The instrument, and it lands **before any Graphiti code**. Extend `evals/retrieval_recall.py` and `evals/memory_recall.py` so a **`graphiti` variant** is measurable side-by-side with the shipped `hybrid_rrf` / durable-memory retriever, and add a `graphiti_vs_baseline` A/B built on the exact `operating_graph_uplift` honest-gate shape (`best_baseline`, `uplift_points`, treatment − baseline, published, exit-0). The repaired-hybrid baseline the A/B reads is a **frozen snapshot** — `baseline/kg_retrieval_2026-07.json` — captured from Gerard's `--live --workspace` retrieval-recall run and the S10 memory-recall live run (§7). No baseline file → the harness reports "baseline not frozen" and the gate is `PENDING`, never a false green.
**Test:** `test_graphiti_variant_registered` (the variant is A/B-able and defaults to the bundled snapshot); `test_uplift_gate_pending_without_frozen_baseline` (absent baseline ⇒ PENDING, not pass); `test_uplift_points_treatment_minus_baseline` (the honest-gate arithmetic). Pure — bundled jsonl + stdlib, no Postgres/LLM/graph DB.
**Notes:** Non-required CI lane, same posture as the sibling evals — the number is the deliverable. This story has **no dependency on Graphiti being built**; it can land and sit green while the baseline is captured.

### S2 · Graphiti on the doc leg behind a default-OFF flag + projection seam — L · _knowledge-graphs J8 / E.3, thesis-T1-b_
Add `graphiti-core` + a graph store (FalkorDB; FalkorDB-Lite embedded for the local edition) as a **new doc-leg backend**, selectable only when `KG_GRAPHITI_TRIAL_ENABLED` is on (default OFF, read through `config.py` — no `os.getenv` outside it, following the `LOG_RELAY_ENABLED` pattern). Route the `schedule_incremental_update:497` pendings from `ingest_agent_output` + document ingest to **Graphiti episodes per workspace** (`group_id = workspace_id`); encode the existing node taxonomy as Pydantic entity/edge types, **reusing the current extraction prompts** as the structured-output schema (not a new prompt corpus). A **projection job** writes Graphiti's state back into the `workspace_graphs` artifacts so `KnowledgeGraphExplorer.tsx`, `api/knowledge_graph.py`, and the `platform_graph_*` tools keep working unchanged during the trial — **one source of truth projected into the old shape, never two permanent substrates** (§5).
**Test:** `test_flag_off_uses_networkx_path` (default OFF ⇒ the current `build_graph` path is untouched); `test_episode_routing_groups_by_workspace` (pendings → episodes, `group_id`=workspace, mocked Graphiti client); `test_projection_writes_workspace_graphs_artifacts` (projection emits graph.json/meta.json/communities.json the UI reads). Pure/mocked at the Graphiti + FalkorDB boundary — no live graph DB in CI.
**Notes:** The projection is what makes this a *trial* and not a fork — the existing surface never sees the swap. Delete-what-you-replace applies **only on a passing verdict** (S6), never speculatively.

### S3 · Entity resolution + bi-temporal invalidation on the doc leg — M · _knowledge-graphs C.2 / C.3_
The two capabilities the in-house merge lacks, exercised through Graphiti on the trial cohort: per-episode **entity resolution** (dedup/resolve against the existing graph, so re-extraction converges instead of duplicating) and **bi-temporal invalidation** (a contradicting fact invalidates — not deletes — its predecessor, preserving auditable history). These are configuration + taxonomy mapping over Graphiti's core, not new algorithms. The eval (S1) is what proves they land: a **duplicate-node-rate** proxy (near-identical labels per 100 nodes) and a **contradicted-fact slice** ("pricing was $49, now $99" ⇒ exactly one live fact) become gold-set assertions.
**Test:** `test_resolution_converges_alias_variants` (three spellings → one entity, mocked resolver); `test_invalidation_supersedes_not_deletes` (old fact marked invalid, still queryable historically); both assert against the S1 gold-set slices. Pure/mocked.
**Notes:** These are the exact C.2/C.3 gaps the review names; if they do **not** move the eval number, that is the trial's honest negative, captured in S6 — not a reason to keep tuning indefinitely.

### S4 · Hybrid retrieval through the graph query path — M · _knowledge-graphs C.9_
When the flag is on, `platform_query_graph` (via `handlers_graph.py:98`) routes to Graphiti's **hybrid search** (semantic + BM25 + graph traversal) instead of term-overlap + BFS; the tool contract and its response shape are unchanged so agents and the UI see an answer, not a rewrite. The answer-quality half of the eval — relationship / multi-hop queries the term-overlap path returns empty on — is scored here against the frozen baseline.
**Test:** `test_query_routes_to_graphiti_when_enabled` (flag on ⇒ hybrid path; flag off ⇒ BFS path, both mocked); `test_query_response_shape_unchanged` (tool contract stable across the swap). Pure/mocked.
**Notes:** This is the story whose number matters most to agents — a graph that resolves and invalidates but still can't answer hasn't earned adoption. Scored, not asserted.

### S5 · Trial guardrails: cost budget, credit precondition, opt-in cohort, ACL boundary — S · _thesis-T1 §4.4 / §4.5 / T1-c_
The trial runs on an **opt-in cohort** (a `config.py` workspace allow-list, default empty), not all tenants. Extraction spend is budgeted and capped through the existing budget seam (Graphiti's 1.36–2.25× per-episode cost is real); the daily **OpenRouter-402 credit outage is a hard precondition** — the trial does not start against an account already hitting its ceiling (surfaced in §8). Read-time ACL stays **PRD-124 team lists / W11 policy plane** — `group_id` is a coarse partition beneath the enforcement point, **never** the ACL itself (adopting it as such would be a downgrade, thesis T1-c).
**Test:** `test_trial_cohort_gates_ingest` (non-cohort workspace ⇒ NetworkX path even with the flag on); `test_acl_stays_team_scoped_not_group_id` (a cross-team read is denied by the PRD-124 path, not permitted by `group_id` alone). Pure.
**Notes:** No `os.getenv` outside `config.py`; the cohort list and budget cap are config, not hardcoded (§4).

### S6 · The verdict: adopt-or-no-op kill-switch — S · _thesis-T1-b exit criterion_
The trial terminates in a **documented decision**, not a lingering second substrate. The S1 A/B produces `graphiti_vs_baseline` uplift; the verdict harness renders it against the stated margin (§7) into one of two paths: **(a) beats-by-margin** → the adopt follow-through is unblocked (retire the in-house `_merge_extractions` resolution + add-only path, delete-what-you-replace — a §8 decision, not auto-executed here); **(b) does-not-beat** → `KG_GRAPHITI_TRIAL_ENABLED` stays OFF, the projection + episode routing are removed, and the in-house resolution+invalidation fallback (knowledge-graphs J4) becomes a *new, then-justified* PRD. Reuses the `TOOL_ROUTING_GRAPH` default-dark precedent — a capability is not shipped until it beats its eval.
**Test:** `test_verdict_adopt_when_uplift_ge_margin`; `test_verdict_noop_when_below_margin` (flag-OFF path clean, no orphan artifacts). Pure.
**Notes:** A negative verdict is a **valid, complete outcome** of this PRD (§12 — it is the specified work, not a descope). The trial's job is the number; the number can say no.

## 5. Sequencing
- **S1 first and blocking.** No Graphiti code (S2–S6) starts until (a) S1's A/B harness is green and (b) the repaired-hybrid baseline is frozen from Gerard's live runs (§7). This is the `⏸ PENDING BASELINE` gate — the whole discipline of the PRD.
- **S2 is the long pole** (new dependency + backend + projection). **S3/S4 build on S2** (resolution/invalidation and hybrid-query both need Graphiti standing). **S5 is parallel** to S2 (guardrails are config + boundary tests). **S6 is terminal** — it reads the S1 number after S2–S4 have run against the cohort.
- **No migration of document data** — documents stay on pgvector (PRD-188); Graphiti runs the *extraction/agent-output* leg only. The projection writes back into `workspace_graphs`, so no schema change to the existing artifacts.

## 6. Verification (CI is the only gate — no local runs)
Per `feedback-no-local-servers`: **no servers, builds, `pytest`, `tsc`, or installs on the dev machine.** All tests are pure/mocked — Graphiti's client and FalkorDB are mocked at the boundary; **no live graph DB in CI**. The eval lanes (`retrieval-recall-eval`, `memory-recall-eval`, and the new `graphiti_vs_baseline` emit) stay **non-required and exit-0** — the number is the deliverable, a sub-margin uplift is an honest business signal, not a red build (the PRD-177 S6 / PRD-188 S5 posture). Flag `KG_GRAPHITI_TRIAL_ENABLED` default OFF means every required lane runs the untouched NetworkX path. Any new route → update the committed `orchestrator/reports/route-manifest.json`. `graphiti-core` + the FalkorDB client are new `requirements.txt` entries; the local edition uses FalkorDB-Lite (embedded, no server) so the open-core fresh-clone lane stays green.

## 7. Baseline capture / eval bar — the gate (measurement decides, not faith)

**This is the point of the PRD.** P2-17 is adopted **only if** Graphiti beats the repaired hybrid baseline on the T3 eval. That baseline does not exist yet, so the bar and the freeze come before the build.

**Freeze FIRST (Gerard's runs — the two numbers that unblock S2):**
1. **Repaired-hybrid retrieval baseline** — `evals/retrieval_recall.py --live --workspace <id>` against a real workspace + its authored gold set, driving the real `RAGService.retrieve` (rerank/hybrid/query-enhancement as shipped). Freeze as `baseline/kg_retrieval_2026-07.json`. This run is "never part of CI" by design — it is the human-run freeze.
2. **Memory-recall baseline (S10)** — `evals/memory_recall.py` against a **live workspace snapshot** with the production retriever injected (`--corpus` + `retriever_factory`). The S10 number is still pending and its own header flags the retriever as not-yet-trustworthy; freezing it honestly (even if sub-target) is the precondition, because the trial must beat *the real baseline*, not the bundled snapshot.

**The bar (the A/B, via the `operating_graph_uplift` honest-gate shape):**
- **Primary:** `graphiti` recall@5 (documents + agent-output) must beat the frozen `hybrid_rrf` baseline by **≥ a stated margin in points** (proposed **≥ +5 pts** recall@5, mean across tenants — Gerard confirms the margin, §8). Uplift = treatment − baseline, published, exit-0.
- **Capability slices that must move (not just the aggregate):** duplicate-node-rate **down** (S3 resolution), contradicted-fact slice resolves to **one live fact** (S3 invalidation), relationship/multi-hop answer-quality **up** vs the term-overlap path (S4 hybrid).
- **Cost ceiling:** extraction spend within the S5 budget cap; the 1.36–2.25× per-episode overhead does not blow the OpenRouter budget (a win on recall that triples spend is surfaced, not silently accepted).

**Kill / no-op criteria (the honest negative is a valid outcome):**
- Uplift **≤ 0**, or **> 0 but below the margin**, or the capability slices don't move → **do not adopt.** The flag stays OFF, S2–S4's Graphiti wiring is removed, and the trial is recorded as a proven negative. The in-house resolution+invalidation fallback (knowledge-graphs J4) becomes a new PRD, justified *only then* because the OSS route was measured and lost.
- Baseline not frozen → gate is **PENDING**, build does not start. No false greens.

*(This trial consumes the same frozen retrieval baseline PRD-197 §7 captures. Freezing it once serves the whole wave — P2-16, P2-17, P2-18 all measure against it.)*
