## Codebase Patterns
- LLM services live in `orchestrator/core/llm/` — standalone classes, no base class needed for analytics services
- Use `httpx.AsyncClient` for async HTTP calls (preferred pattern), `requests` for sync
- DB session via `from core.database.database import SessionLocal` — create, use, close manually
- `LLMUsage` model in `core/models/core.py` — fields: workspace_id, model_id, provider, tier, input_tokens, output_tokens, total_tokens, input_cost, output_cost, total_cost, is_byok, latency_ms, status, error_message, created_at
- `UserApiKey` model — encrypted_key decrypted via `get_encryption_service().decrypt()`
- OpenRouter headers: `Authorization: Bearer {key}`, `HTTP-Referer: https://automatos.app`, `X-Title: Automatos AI`
- No formal mypy/pyright setup — typecheck = `python -m py_compile` succeeding
- API routers in `orchestrator/api/` — FastAPI pattern with `RequestContext` + `get_request_context_hybrid`
- Resolve BYOK keys via `_resolve_openrouter_key` pattern: query `UserApiKey` (workspace + provider + is_active), decrypt, fallback to env var, 404 if missing
- llm_analytics.py router prefix: `/api/analytics/llm` — already registered in main.py
- Composio workspace scoping: Agent.workspace_id for agent filtering, ComposioEntity.workspace_id → ComposioConnection.entity_id for connections
- AgentAppFeature has no direct workspace_id — join through Agent.id to scope by workspace
- composio_analytics.py router prefix: `/api/analytics/composio` — registered in main.py
- analytics_charts.py router prefix: `/api/analytics/charts` — registered in main.py
- PandasAI service accessed via lazy `get_pandasai_service()` — returns None if not installed/configured, use 404 for unavailable
- `generate_insight(question, rows, columns)` returns `{"summary": str, "charts": [{"filename", "mime_type", "base64"}]}`
- `LLMModel` registry: `input_cost_per_1k_tokens`, `output_cost_per_1k_tokens`, `context_window`, `capabilities` (JSON dict), `display_name`, `provider` — query by `model_id` for metadata fallback
- PERIOD_MAP in llm_analytics.py supports: 1h, 24h, 7d, 30d, 90d
- Previous period comparison: `prev_start = since - delta`, filter `created_at >= prev_start AND < since` for period-over-period change %
- Use `func.count(func.distinct(func.date(col)))` for days-with-data count — more accurate than raw period length for daily averages
- Frontend hooks: `apiClient.request<T>(endpoint, options)` for API calls, handles auth + workspace headers
- Frontend 404 handling in hooks: catch error, check `err.message.includes('404')`, return null for "not configured" state
- Frontend cache keys: extend `unifiedAnalyticsKeys` object with new namespaces for cache key consistency
- Frontend mutations: use `useMutation` from tanstack + `queryClient.invalidateQueries()` for cache busting on write operations
- tanstack react-query v4: mutations use `isLoading` (not `isPending` which is v5) — check `syncMutation.isLoading` for loading state
- Glass card pattern: `<Card className="glass-card">` + `CardHeader`/`CardContent` for all analytics cards
- Color-coded progress bars: green <70%, yellow 70-90%, red >90% — reuse `getUsageColor(percentage)` pattern from plan-usage
- "Not configured" state: render centered icon + message + link to settings when hook returns null (404 = no key)

  - Calculates daily average cost from `llm_usage` for the requested period
  - Projects to 30-day monthly cost: `daily_avg * 30`
  - Returns: `current_period_cost`, `daily_average`, `projected_monthly`, `change_percent` (vs previous period), `projected_by_model`, `projected_by_provider`
  - Uses `func.distinct(func.date(...))` to count actual days with data for accurate daily averages
  - Previous period comparison: shifts window back by the same delta, computes percent change
  - Added `CostProjectionResponse` and `ProjectedItem` Pydantic response models
- Files changed: `orchestrator/api/llm_analytics.py` (modified — added 2 schemas + 1 endpoint)
- **Learnings for future iterations:**
  - Use `func.count(func.distinct(func.date(col)))` to get days with data rather than dividing by period length — avoids inflated averages when usage is sparse
  - Previous period comparison pattern: `prev_start = since - delta`, filter `>= prev_start AND < since`
  - Round financial values with `round(val, 6)` to avoid floating point noise in JSON responses
