## A. What it is

The platform's document-grounding arm: a single retrieval service (PRD-157) that scopes every search through one fail-closed tenancy/team choke point, searches per-workspace AWS S3 Vectors indexes over an OpenRouter-embedded corpus, applies RRF fusion / optional rerank / feedback penalties / parent-context hydration, and assembles numbered-citation context under a model-aware token budget — plus the full ingestion arm folded in (multi-format extraction, 5-strategy chunker, optional multimodal PDF processors, Composio cloud sync) and a set of agentic document tools (`read_document`, `grep_documents`, pinning). It is how Auto, the agents, the widget, and the planners see workspace knowledge; in chat it is deliberately tool-driven (agentic retrieval), and only the planning pack auto-injects it.

## B. What it does (real implementation + data path)

**Ingestion.** `POST /api/documents/upload` validates MIME/extension/size and dedups by content hash *within* the workspace (`orchestrator/api/documents.py:113-165`), then **synchronously awaits** the full process inside the request (`api/documents.py:251`). `DocumentManager` (psycopg2 raw connections — a third DB-access idiom beside SQLAlchemy and asyncpg) extracts text (pdfplumber incl. tables-to-markdown, docx, xlsx/csv; `modules/rag/ingestion/manager.py:500-560`), chunks via `SemanticChunker` in **TOPIC_COHERENCE keyword-overlap mode with embeddings explicitly disabled** (`manager.py:307-317`; `modules/rag/chunking/semantic_chunker.py:80,201-242`; target 500 chars), embeds via the centralized `EmbeddingManager` — production is **OpenRouter `qwen/qwen3-embedding-8b`, 4096-dim** (`orchestrator/.env`; `core/llm/embedding_manager.py:66-135`) — and dual-writes: chunk text to Postgres `document_chunks`, vectors+500-char preview to a **per-workspace S3 Vectors bucket** (`manager.py:1273-1364`; `modules/search/vector_store/backends/s3_vectors_backend.py:219-289`, preview truncation at `:249`). Live store confirms the corpus is real: **644 documents / 19,130 chunks** ([census](evidence/data/census.md)). A parallel multimodal leg (camelot tables, OCR/vision images, regex formulas → `knowledge_items`/`kb_tables`/`kb_formulas`; `manager.py:863-1061`) exists, but the PDF table/image extraction pass is gated by `getattr(self, 'enable_multimodal', False)` which **no caller ever sets** (`manager.py:1065`; repo-wide grep: zero assignments). Cloud sync (PRD-42) lists/downloads via Composio for GOOGLEDRIVE/DROPBOX/ONEDRIVE/BOX and reuses the same ingest path (`modules/rag/services/cloud_sync_service.py:198-350`) — **manual trigger only**; no scheduler references it, so synced corpora go stale unless a human re-syncs. Agent outputs also enter the corpus via the PRD-164 S3 flywheel (`manager.py:709-719` `source_type='agent_output'`; callers at `api/missions.py:878`, `modules/tools/discovery/handlers_documents.py:236`).

**Retrieval.** One entry point, `RAGService.retrieve` (`modules/rag/service.py:223-355`), serves every consumer:
1. **Scope** through `build_retrieval_filters` — fail-closed (no workspace ⇒ `RetrievalScopeError` ⇒ empty result), canonical team normalization, one SQL predicate reused everywhere (`modules/rag/retrieval_filters.py:78-140`).
2. **Query enhancement** — HyDE, decomposition, expansion, concept extraction: **four sequential LLM round-trips** before any search (`modules/rag/query_enhancer.py:96-112,125-226`), fail-soft to the raw query.
3. **Multi-query RRF** over up to 5 variants, k=60 (`service.py:584-636`) — fusing *vector-only* result lists.
4. **Vector search** on the per-workspace S3 backend, one initialized backend cached per workspace (`service.py:889-904`), with the F005 fix live: explicit workspace filter passed (`service.py:936-941`) and enforced in the backend — mismatched filter refuses, mismatched hit dropped, bucket template must contain `{workspace_id}` (`s3_vectors_backend.py:51-55,153-217`).
5. **Team post-filter** through `allowed_document_ids`, degrading to public-docs-only on DB error (`service.py:535-582`; `retrieval_filters.py:143-183`).
6. **Optional Cohere rerank** — default OFF (`rag_rerank_enabled` default "false", `service.py:147`; hardcoded `enable_reranking=False` in the search endpoint, `api/documents.py:1470`; `rerank-v3.5` via httpx, `core/llm/rerank_manager.py:24`), and **no `COHERE_API_KEY` exists in the prod env** (grep count 0), so reranking cannot run today.
7. **Feedback penalty** (W9/F070): negative `rag_feedback` rows de-rank a document ×0.5 within 90 days (`service.py:331-334,414-510`; `config.py` `RAG_FEEDBACK_*` defaults ON).
8. **Parent-context hydration** ±1 chunk in one batched asyncpg query, workspace-pinned via a `documents` join (`service.py:985-1080`) — this is what upgrades the 500-char S3 preview to full chunk text; on failure the LLM sees previews (`service.py:1075-1078`).
9. **Scoring + budget** — similarity × word-count/ASCII-art quality heuristic × exponential same-source penalty (`service.py:717-753,809-841`), then greedy **whole-chunk selection under a token budget** with tiktoken counts (`modules/rag/budget.py:89-122`) and RAGFlow-style numbered citations `[1]..[n]` + source map (`budget.py:125-175`).

**Consumers.** Agent tools `search_knowledge`/`semantic_search` (min_similarity 0.65; `modules/agents/services/agent_platform_tools.py:288-300,401`), the planning pack section — the only auto-injection, PLANNING mode only (`modules/context/sections/planning_knowledge.py:55`; `modules/context/modes.py:146`), widget document search (`api/widgets/documents.py:101`), NL2SQL schema grounding (`modules/nl2sql/service.py:1184`), the UI semantic-search endpoint (`api/documents.py:1473-1479`). Beside vector search sit the **agentic document tools**: paged token-budgeted `read_document` and regex `grep_documents`, both scoped through the same choke point (`modules/tools/discovery/handlers_documents.py:397-490,493-570`), and per-chat **document pinning** whose content is injected as a system message every turn (`modules/rag/pinned_context.py:93-167`; `consumers/chatbot/service.py:1036-1059,2016-2017`).

## C. Honest quality — inspected against real behaviour and data

**What is genuinely good.** The July verdict ("best-integrated slice", §2) still holds *architecturally*: one retrieval path, one grep-able fail-closed scope builder with a real test estate (21 tests in `tests/test_retrieval_filters.py` + tenancy matrix + hydration/atomicity/perf/feedback suites), one token budgeter shared with tool-result truncation and pinning, citation-grade assembly, and — ahead of most RAG stacks — real agentic `read_document`/`grep_documents` tools that let the model iterate rather than accept one static chunk bundle. The F005 tenant closure is real at both the vector and hydration layers. The corpus is real (19,130 chunks).

**The defects, with evidence:**

1. **The feedback→ranking loop has a soul but no mouth.** `rag_feedback` has **0 rows ever** despite months of chat over the 19k-chunk corpus ([rag-feedback](evidence/data/rag-feedback.md)). Root cause is not user apathy: **nothing produces the signal.** Repo-wide grep finds zero non-test callers of `POST /api/rag/feedback`; the chat thumbs UI posts to `/api/chat/vote`, which writes the `Vote` table and never touches `rag_feedback` (`frontend/components/chatbot/message-actions.tsx` → `frontend/lib/chat/api.ts:42-51` → `api/chat.py:640` → `consumers/chatbot/service.py:454-485`). The W9/F070 read-side fix is correct code reading an empty table — the "learning from retrieval feedback" claim is currently fiction.
2. **Silent quality cliffs, and a probably-dark production retrieval plane.** Every failure in `_get_candidates` — including embedding-API errors — is swallowed into an empty candidate list (`service.py:981-983`), which surfaces as the *legal* answer "No relevant context found." Query embedding rides the same OpenRouter key that has been failing **402 insufficient-credits daily since ~2026-06-16** (playbook LLM steps; deliverables stopped 06-16 — [real-data inventory](evidence/real-data-inventory.md) §first-look 3). A 402 in `OpenRouterEmbeddingProvider.generate_embedding` raises (`core/llm/clients/openrouter_embedding.py:95-108`) → swallowed → empty retrieval. **Strong inference: RAG retrieval has been returning nothing in production for ~2.5 weeks, and no dashboard can tell.** Worse, the config-time fallback is `DeterministicEmbeddingProvider` — **hash-seeded random vectors** with only a log warning (`core/llm/clients/base.py:200-225`; selected on missing key/provider at `embedding_manager.py:90-93,113-118`), which would make retrieval *quietly meaningless* rather than empty.
3. **"Hybrid search" is decorative.** `hybrid_search_enabled` / `hybrid_vector_weight` / `hybrid_keyword_weight` exist only as dataclass fields (`service.py:125-127`); no keyword/BM25/tsvector leg exists anywhere in the module (grep-proven). RRF fuses vector variants only. The chunk text sits in Postgres where FTS would be nearly free.
4. **Reranking is unreachable.** Integration code is fine (`rerank_manager.py`), but the setting defaults false, the search endpoint pins it false, and no Cohere key is configured — the pipeline's highest-leverage precision stage (see D) has never run.
5. **Observability reads a table only the demo surface writes.** Retrieval stats/recent-queries read `document_usage` `rag_query` events (`service.py:1204-1216,1307-1326`), but only the UI endpoints insert them (`api/documents.py:1223,1508,1591`); the agent-tool and planning retrievals — the ones that matter for autonomy — log nothing there. F046 is also still live: two endpoints call the nonexistent `RAGService.test_rag_config` and 500 on every hit (`api/context.py:182`, `api/system.py:330`; residual map confirms, NOT DONE).
6. **Chunking is keyword-Jaccard, not semantic, and chunks carry no context.** Live path: TOPIC_COHERENCE with `_use_embeddings=False`, 500-char targets (`manager.py:307-317`). Entropy/coherence metrics are computed and stored but nothing downstream consumes them. No chunk-level document context (title/section situating) is generated — the exact gap Anthropic's contextual retrieval attacks (see D).
7. **Cross-workspace dedup defect in the shared ingest path.** `DocumentManager.upload_document` dedups by `file_hash` with **no workspace predicate** (`manager.py:737`), while the row INSERT stamps `workspace_id` (`:774`). Five production callers use this path (missions flywheel `api/missions.py:878`, platform tool, wizard, cloud sync, `api/documents.py:896`). A byte-identical file uploaded by workspace B returns workspace A's document id — which B's fail-closed filters then make unretrievable. Functional dead-end (the fail-closed layer prevents content leakage, so the impact is a broken flywheel write, not a read).
8. **Dark features advertised as live.** Pinning: backend + injection are real, but **zero frontend callers and no platform tool** (grep across `frontend/` and `modules/tools/`) — users cannot pin anything. Multimodal: `search_tables`/`search_images`/`search_formulas`/`search_multimodal` are registered as chat search tools (`consumers/chatbot/service.py:148-151`) but the ingestion flag that would feed their store is never enabled (`manager.py:1065`) — tools that search an unfed store. The 950-line `ContextOptimizer` is still constructed and used only as a truthiness gate (`service.py:185,342`; F079 NOT DONE) — it decides *which branch runs* and contributes zero math.
9. **Latency/cost shape is heavy for a tool call.** Enhancement = 4 sequential LLM round-trips, then up to 5 vector searches + hydration; a `search_knowledge` call plausibly costs 3–10 s before the agent even sees results (see H). No caching of enhanced queries.
10. **No measurement.** No retrieval gold set, no recall@k, no faithfulness eval anywhere ([repo-eval-artifacts](evidence/data/repo-eval-artifacts.md) — evals exist for tool-routing/NL2SQL/W7 only). Quality is a vibe; the seed complaint of this whole review.

**Maturity score: 3 / 5.** The scaffold (choke point, budgeter, citations, agentic tools, tenant isolation) is genuinely strong 4/5 engineering, and it is exactly the OS-shaped integration a bolt-on vendor cannot give. But the *quality* half is unproven and partly fictional: the learning loop has no input, the precision stage has never run, hybrid is a config mirage, the live plane is probably returning empty right now with zero signal, and nothing is measured. A retrieval system whose emptiness is indistinguishable from its success cannot be scored 4.

## D. Competitive teardown

- **Anthropic contextual retrieval** — prepends a 50–100-token LLM-generated situating context to every chunk before embedding, adds a contextual BM25 leg, then reranks: **−35%** retrieval-failure from contextual embeddings alone, **−49%** with BM25, **−67%** (5.7%→1.9% top-20 failure) with rerank; one-time annotation cost **$1.02 per million document tokens** with prompt caching ([anthropic.com/engineering/contextual-retrieval](https://www.anthropic.com/engineering/contextual-retrieval)). Automatos has none of the three legs live: no chunk context, no BM25, rerank dark. This is the single most actionable playbook for this module.
- **Cohere Rerank 4 (Pro/Fast)** — the current rerank bar: Rerank 4 Pro ~1627 ELO vs v3.5 ~1457 on Agentset's reranker arena, biggest gains on business/finance queries; $2.50 (Pro) / $2.00 (Fast) vs $1.00 (v3.5) per 1k searches ([agentset.ai/blog/cohere-reranker-v4](https://agentset.ai/blog/cohere-reranker-v4), [cohere.com/pricing](https://cohere.com/pricing)). Automatos hardcodes `rerank-v3.5` as default and cannot run even that (no key).
- **LlamaIndex** — the ingestion/retrieval breadth benchmark: hundreds of integrations, LlamaParse for hard documents, semantic splitting, hybrid + recursive retrieval, metadata filtering, composable retrievers ([developers.llamaindex.ai](https://developers.llamaindex.ai/python/examples/low_level/retrieval/), [futureagi.com/blog/what-is-llamaindex-2026](https://futureagi.com/blog/what-is-llamaindex-2026)). Automatos' ingestion (8-ish file types, 4 cloud providers, one chunker mode) is far narrower, and its parse quality for messy PDFs is pdfplumber-grade. Where Automatos is *not* behind: LlamaIndex gives no tenancy, no team ACLs, no policy integration — the parts Automatos already owns.
- **Vectara** — managed RAG with a per-query **Factual Consistency Score** (HHEM-2.x hallucination detection, beats GPT-4 as a judge on that task) plus Boomerang embeddings and a citation-tuned generator ([vectara.com/business/platform/models](https://www.vectara.com/business/platform/models), [huggingface.co/vectara/hallucination_evaluation_model](https://huggingface.co/vectara/hallucination_evaluation_model)). Automatos returns citations but has zero groundedness scoring — no per-answer signal that retrieval was actually used faithfully.
- **Morphik** — open-source multimodal RAG on ColPali-style patch embeddings, skipping OCR entirely; ~86% on ViDoRe visual-document retrieval ([ycombinator.com/companies/morphik](https://www.ycombinator.com/companies/morphik), [morphik.ai/blog/stop-parsing-docs](https://www.morphik.ai/blog/stop-parsing-docs)). Automatos' multimodal leg is the older OCR/camelot paradigm — and dark anyway. If diagram/table-heavy verticals matter, this is the modern answer, not enabling the current flag.
- **The agentic-search shift** — the 2026 trend Automatos is accidentally well-positioned for: Claude Code dropped vector RAG for glob+grep+read; an Amazon Science AAAI 2026 result measured agentic keyword search at ~94.5% of RAG faithfulness with zero vector store ([dev.to — grep vs vector retrieval](https://dev.to/pueding/is-grep-all-you-need-grep-vs-vector-retrieval-for-agentic-search-534k), [sesamedisk.com](https://sesamedisk.com/direct-corpus-interaction-ai-retrieval/)). Automatos already ships scoped `grep_documents` + paged `read_document` through the same choke point — a genuine strength worth saying plainly; its problem is not the paradigm, it is that nothing measures either paradigm's quality here.
- **Substrate note (S3 Vectors):** now GA with 2B-vector indexes and warm-query latencies ~100–380 ms, but AWS itself positions it for *infrequent* queries and ~20% of queries return K−1 results ([aws.amazon.com/blogs/aws — S3 Vectors GA](https://aws.amazon.com/blogs/aws/amazon-s3-vectors-now-generally-available-with-increased-scale-and-performance/), [dev.to — real performance numbers](https://dev.to/siddhantkcode/aws-s3-vectors-at-scale-real-performance-numbers-at-10-million-vectors-2lno), [docs.aws.amazon.com limitations](https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-vectors-limitations.html)). At 21 workspaces / 19k chunks this is fine and cheap; it is not a high-QPS substrate if the widget leg scales.

**Where Automatos actually stands:** mid-pack. Ahead of framework-assembled RAG on tenancy, budgeting, citations, and agentic tools; behind the state of the art on every retrieval-*quality* lever (chunk context, hybrid, rerank, groundedness, eval), and behind managed platforms on ingestion robustness and multimodal.

## E. Build / extend / adopt / replace — verdict

**EXTEND the in-house spine; ADOPT three specific externals into it. Do not replace.**

- **Keep (build-owned):** the choke point, budgeter/citations, S3-per-workspace substrate at current scale, and the agentic read/grep tools. No external platform (Vectara, Morphik, LlamaIndex-as-a-service) drops into the workspace/team/policy fabric this is welded to; replacing would forfeit the module's actual differentiator — scoped, budgeted, citation-grade retrieval *inside* the agent OS — to gain features that are adoptable piecemeal. Adopting a full platform also re-relocates, not solves, the quality problem (their ingestion still needs the tenancy weld).
- **Adopt 1 — Cohere Rerank** (flip the existing integration live; add key, default `rag_rerank_enabled=true`, upgrade default model to Rerank 4 Fast): ~$2/1k retrievals, the cited −67% failure leg, zero new code beyond config.
- **Adopt 2 — contextual chunk annotations** (Anthropic's pattern, not a product): Haiku-class model at ingestion, ~$1.02/M document tokens one-time, prepended before embedding. Integration point: `manager.py:_process_document` before `_persist_chunks_and_vectors`.
- **Adopt 3 — RAGAS (or DeepEval) for the eval harness** (feeds T3): faithfulness / answer relevancy / context precision / context recall as the module's tracked numbers ([docs.ragas.io metrics](https://docs.ragas.io/en/v0.1.21/concepts/metrics/)). Building a bespoke judge first is not earned.
- **Build (small, no external exists inside this fabric):** the Postgres tsvector BM25 leg fused into the existing RRF (chunk text already in `document_chunks`), the zero-result/embedding-liveness canary, and the feedback wiring.

## G. Quality metric

**Today's number: does not exist.** No gold set, no recall@k, no faithfulness score anywhere; the only quantified facts are `rag_feedback = 0 rows` and an unmeasured zero-result rate. Proposed, in order of standing-up cost:

1. **Zero-result rate + retrieval-error rate** (online, this week): instrument `RAGService.retrieve` to distinguish `empty` / `error` / `ok` (today error masquerades as empty, C-2) and emit per-day rates. This metric alone would have caught the ~06-16 outage in one day.
2. **recall@k / MRR on a workspace gold set** (offline, nightly): 50–100 question→document_id pairs authored from the real 644-doc corpus; run through `retrieve()` with enhancement on/off, rerank on/off — this also finally answers "does HyDE/RRF pay for its 4 LLM calls" with a number.
3. **RAGAS faithfulness + context precision** on sampled `search_knowledge`-grounded answers (LLM-judge, calibrated on a small human-labelled set) — the generation-side complement.
4. **Feedback volume** (`rag_feedback` rows/week) — currently a 0 that should be an alarm, becomes a health metric once J-1 lands.

## H. Cost note (informational)

Per `retrieve()` with enhancement ON (production default): 4 sequential small LLM calls (~1.5–3k tokens total ≈ $0.001–0.004 at 4o-mini/Haiku-class prices) + 1–5 query embeddings (qwen3-embedding-8b at $0.01/M tokens via OpenRouter — [openrouter.ai/qwen/qwen3-embedding-8b](https://openrouter.ai/qwen/qwen3-embedding-8b) — effectively $0) + 1–5 S3 Vectors queries (fractions of a cent) + one asyncpg hydration query. **LLM enhancement dominates both cost and latency (est. 3–10 s sequential).** Ingestion: embedding a document ≈ $0.01/M tokens (negligible); adding contextual annotations would add ~$1.02/M document tokens one-time; enabling Rerank 4 Fast adds ~$0.002/retrieval. The heavy line item is not money, it is latency inside agent turns — enhancement calls are sequential where they could be parallel or cached.

## I. UX / surface

- **Knowledge/Documents page** (`frontend/components/documents/`): upload, processing status, semantic search test (`semantic-search.tsx` → `use-semantic-search-api`), team multi-select. Adequate for admin; blind to quality.
- **Missing surfaces, concrete:** (1) **Pin-to-chat UI** — the S5 feature is backend-complete and frontend-absent; a pin affordance on document rows + a pinned-docs chip row in the chat composer would light up a dead feature (or kill it — Gerard's call, §12). (2) **Feedback affordance that feeds `rag_feedback`** — today's thumbs write `Vote`; either extend the vote handler to also write `rag_feedback` with the turn's retrieved doc ids, or add a per-citation "not relevant" control; without this the Command Center can never show retrieval quality. (3) **Citations in chat** — the backend emits `[1]..[n]` + `sources_map`; the chat UI should render them as clickable source chips (opening `read_document` paging), making grounding visible to clients. (4) **Command Center retrieval widget** — zero-result rate, retrieval-error rate, corpus freshness (last successful ingest/sync per source), embedding-provider liveness; the June outage was invisible precisely because no surface owns "is retrieval alive". (5) **Retrieval trace inspector** (mirror of the PRD-166 field inspector): for a given query show candidates → filters → rerank → budget decisions; this is the debugging surface for "why did Auto say there's nothing about X".
- **Honesty cleanups:** the RAG-config "test" buttons in whatever calls `api/context.py:182` / `api/system.py:330` hit permanently-500 endpoints (F046) — fix or remove; retrieval "recent queries/response time" stats show only UI searches, not agent retrievals (C-5) — relabel or instrument the real path.

## J. Upgrade path (impact × effort, judged by North-Star impact)

1. **Make retrieval failure visible and typed** (S) — `RAGResult.error` distinct from empty; zero-result/error-rate metric + embedding-provider canary; alert on sustained spikes. *Directly prevents weeks-long silent grounding outages (C-2) — the single biggest autonomy-quality risk in this module.* Include: stop falling back to `DeterministicEmbeddingProvider` in production paths — fail loud instead of retrieving noise.
2. **Give the feedback loop a mouth** (S) — wire chat votes (and widget thumbs) to `rag_feedback` with the turn's retrieved document ids; the W9 read side then starts doing real work on day one. Alternative if not wired: remove the penalty claim from docs/UI (honesty).
3. **Turn on reranking** (S) — Cohere key + default-on + Rerank 4 Fast; measured −67% failure leg for ~$2/1k retrievals. Gate by the eval in J-5 to prove it here.
4. **Add the BM25 leg** (M) — Postgres tsvector over `document_chunks.content`, fused via the existing RRF; delete the decorative hybrid knobs or make them real. Exact-term queries (SKUs, error codes, names — the widget/commerce cases) are where pure-vector fails hardest.
5. **Stand up the retrieval eval** (M) — gold set + nightly recall@k/MRR + RAGAS faithfulness (G); CI-gated like the NL2SQL harness. Feeds T3; every other item here gets its before/after number from this.
6. **Contextual chunk annotations at ingestion** (M) — Anthropic pattern, ~$1/M doc tokens one-time, plus reprocess the 644-doc corpus via the existing background reprocess path (`api/documents.py:1808-1930`).
7. **Move ingestion off the request thread** (S/M) — `upload` currently awaits extract+chunk+embed+S3 inline (`api/documents.py:251`); use the existing BackgroundTasks pattern + status polling that reprocess already has.
8. **Fix the cross-workspace `file_hash` dedup** (S) — add the workspace predicate at `manager.py:737`; unblocks the PRD-164 flywheel from silently no-oping on duplicate content across tenants.
9. **Parallelize/cache query enhancement** (S) — run HyDE/decomposition/expansion concurrently (asyncio.gather) and cache per (workspace, query-hash); cuts 3–10 s tool-call latency roughly in half with zero quality change.
10. **Decide the dark features** (Gerard's call, §12 — surfacing, not deferring): (a) pinning — ship the UI + a `platform_pin_document` tool, or delete S5; (b) multimodal — either adopt the ColPali/Morphik-style visual path for the verticals that need it and feed the store, or unregister `search_tables`/`search_images`/`search_formulas` from the chat tool list until it has data; (c) delete the `ContextOptimizer` zombie, the dead `context_type` param, and repair-or-remove the two F046 endpoints (PRD-184 material that was never authored).
11. **Cloud-sync freshness** (M) — scheduled incremental re-sync per connection (the manual-only sync is a staleness bug for any client whose knowledge lives in Drive); reuse the heartbeat/scheduler plane.

**North-Star through-line:** every retrieval this module serves is an agent grounding itself before acting for a client. Items 1–2 make grounding *honest* (failures visible, quality signal flowing), 3–6 make it *measurably better* (the cited 49–67% failure-reduction stack + the number to prove it), 7–11 make the corpus *fresh and complete*. None of it is moat framing; all of it is "the agent's answer cites the right document more often, and someone can tell when it doesn't."
