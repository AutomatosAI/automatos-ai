## A. What it is

The agent definition and capability plane: how an agent comes to exist (CRUD, seeding, marketplace clone), what it *is* (model config, persona, org-chart position, governance blueprint), what it *knows how to do* (git/plugin/builtin-backed SKILL.md skills with 3-level progressive disclosure), and the single execution spine every non-chat surface funnels through (`AgentFactory.execute_with_prompt` — the July F001 site, now W1-hardened). Folded in per the capability map: the persona library (PRD-42), the plugin/community marketplace pipeline with its two-stage security scanner, and the cascade installer that makes a one-click marketplace install pull in models, skills, plugins and tool assignments. This module is where "give Auto and the agents a new capability without engineering time" either works or doesn't — which makes it a first-order North-Star lever.

## B. What it does — real implementation and data path

### B.1 Definition plane

The `Agent` ORM row is rich and carries everything the platform has bolted on since PRD-37: workspace tenancy, marketplace fields (`owner_type`, `install_count`, `is_approved`), persona assignment (`persona_id` / `custom_persona_prompt` / `use_custom_persona`), voice profile, system-agent flags, and Mission-Zero org structure (`team`, `job_title`, `reports_to_id`, `responsibilities`) — `orchestrator/core/models/core.py:195-280`. CRUD is the canonical workspace-scoped router `api/agents.py:32` (create `:403`, list with system-agent visibility rules `:487-562`, org chart `:570`, update `:828`, delete with a Playbook-reference guard that blocks FK-orphaning deletes `:948-967`). Every create/update fires a background semantic re-embed for agent matching (`:39-66`).

Personas: 43 rows live (10 seeded from `core/seeds/seed_personas.py` + workspace customs), global + workspace scopes, CRUD at `api/personas.py:165-497`, consumed by IdentitySection via `Agent.persona.system_prompt` with the custom-prompt override checked first (`agent_factory.py:807-811`).

Blueprints: per-workspace governance rules (`min_tools`, `require_system_prompt`, `max_budget_per_run`, `allowed_models`) as JSONB on `agent_blueprints` (`core/models/blueprints.py:16-42`), validated by `services/blueprint_validator.py` from three call sites — platform tools, agents.py create/update warnings, and coordinator pre-dispatch (`blueprint_validator.py:4-8`).

### B.2 Skills plane

The `Skill` row stores the SKILL.md body in `prompt_template`, tool definitions in `tools_schema`, and git/plugin provenance (`core/models/core.py:340-385`). **There is no `priority` column** — that matters below. Four ingestion paths write skills:

1. **Git import** — `SkillLoader.add_git_repository` (`modules/agents/services/skill_loader.py:249`): sanitized clone (domain allowlist, branch validation, `--` separator via `core/security/git_sanitizer`), `rglob("SKILL.md")` discovery, YAML-frontmatter parse (`:133-165`), a 42-pattern dangerous-content scan per file (`:107-130`, delegating to the plugin scanner's `quick_scan`), then upsert scoped to `(name, source_id, workspace_id IS NULL)` (`:736-740`) plus `SkillFile` rows for L3 files (`:794-854`).
2. **Plugin materialization** — `core/services/skill_materializer.py:162-164` turns an approved marketplace plugin's content into global skills with `skill_source="plugin:{slug}"`.
3. **Builtin seeding** — `core/seeds/seed_auto_agent.py:81-133` upserts the 26.5 KB `platform-management` skill from disk and attaches it to every workspace Auto; a content-hash freshness check hot-reloads it at read time (`skill_loader.py:931-970`).
4. **Workspace-authored** — `api/workspace_skills.py:617` (PRD-71 create/patch/fork).

Progressive disclosure is a 3-level design copied from the Claude-skills idea: L1 metadata (~50 tokens, `load_skill_metadata` `:860-924`), L2 core content (`load_skill_core` `:976-1053`, DB `prompt_template` first, filesystem fallback), L3 on-demand resources with an LRU cache (`load_skill_resource` `:1059-1131`) and script-path resolution (`get_skill_script_path` `:1137-1185`).

**How skills actually reach a prompt:** `SkillsSection` (priority 4) renders the agent's attached skills every turn — the "primary" (highest-priority active) skill uncapped, auxiliaries sharing a 5,000-token budget (`modules/context/sections/skills.py:24-100`), plus a "Using Your Skill Tools" instruction block extracted from `tools_schema` (`:89-98`). There is **no trigger-based activation**: an assigned skill's full L2 body is in every prompt, every turn.

### B.3 Execution spine

Ten production entry points construct `AgentFactory(db_session=db)` and call `execute_with_prompt`: board (`api/board_tasks.py:1026`), Missions coordinator (`services/coordinator_service.py:1948`), Playbooks (`api/recipe_executor.py:326`), scheduled tasks (`services/scheduled_task_service.py:400`), heartbeats (`services/heartbeat_service.py:923`), webhooks (`api/webhooks.py:635`), Composio triggers (`api/composio.py:814`), channels (`channels/base.py:169`), chat suggestion paths (`consumers/chatbot/service.py:540`), and the task runner (`core/task_runner/local.py`). The spine (`modules/agents/factory/agent_factory.py:855-1232`):

- **Activation** (`:682-846`): loads the agent with eager skills+persona (`modules/agents/queries.py:27-44`), resolves the model through a genuinely robust ladder — agent `model_config` → orchestrator/system tier from settings → provider-mismatch auto-correction (`_resolve_provider_for_model` `:343-416`, e.g. slash-models re-routed to OpenRouter, `claude-*` forced to anthropic) → BYOK → credential store → env key (`_resolve_api_key` `:418-493`) → OpenRouter fallback when the direct provider has no credential (`:777-786`).
- **Prompt build**: ContextService is the single prompt builder for the non-chat path (`:924-930`, `TASK_EXECUTION` mode default), with the PRD-127 attachment chokepoint after the user message (`:991-1021`) and Composio per-action schema injection or hint fallback (`:1281-1364`).
- **Loop**: the shared `ToolLoopExecutor` — the F001 fix is live (`content_truncate_tokens=0` at `:1079`; residual map confirms the ctor accepts it and a seam-guard test asserts the removed kwarg raises, `tests/test_prd171_execution_spine.py:89,141`) — plus empty-response synthesis from tool results (`:1104-1111`), up-to-2 truncation continuations (`:1114-1148`), and retry with backoff (`:1026-1214`).
- **Signals**: in-process `AgentRuntime.update_metrics` (`:178-195`), monitoring record (`:1175-1183`); durable per-agent stats are written only by the Playbook executor (`api/recipe_executor.py:2017` → `agents.performance_metrics`).

### B.4 Marketplace plane

Five routers share the marketplace surface: community agents (`api/marketplace.py`), public plugins (`api/marketplace_plugins.py`), admin plugin pipeline (`api/admin_plugins.py` — upload `:139`, GitHub import `:511`, approve/reject/deactivate), per-agent plugin assignment (`api/agent_plugins.py`, including an assembled-context preview `:274`), and workspace skill enablement (`api/workspace_skills.py`). Install is clone-plus-cascade: `clone_agent_to_workspace` (`modules/tools/discovery/cascade_installer.py:78-120`) then `cascade_agent_dependencies` — model install with provider normalization, skills, plugins, tool assignments, and OAuth warnings (`cascade_installer.py` + `api/marketplace.py:468-556`).

Every uploaded plugin goes through `PluginScanService.scan_plugin` (`core/services/plugin_security_scanner.py:462-568`): stage 1 = 42 static patterns across code/network/filesystem/prompt-injection groups with auto-block on critical (`:23-85, :497-526`); stage 2 = a Claude scan (`llm_security_scan` `:300-443`) producing a 0-100 risk score → `safe` / `review_required` / `blocked` (`:532-540`).

## C. Honest quality — maturity **2.5 / 5**

The spine is real and the ingestion pipelines are real; the definition/skills layer is corrupted in production and ringed by dead or dishonest API surface.

**What genuinely works (evidence, not self-description):**

- The F001 fix holds and is guarded: unconditional `ToolLoopExecutor(content_truncate_tokens=0)` construction (`agent_factory.py:1075-1080`), through-the-factory acceptance test plus a seam-guard asserting the removed kwarg fails loudly (`tests/test_prd171_execution_spine.py:89,141`; residual map F001 FIXED). All ten entry points converge on this one code path, so the July "board delivered every task into a dead engine" failure class is closed at its root.
- The model-resolution ladder saves real executions: 59 agents carry fresh success-rate telemetry through 2026-07-04 — heartbeat and Playbook agents are executing daily through this factory (success 0.40-0.86; the sub-0.9 rates are consistent with the OpenRouter-402 outage the W1 recon found, i.e. the numbers are *honest*).
- The skill content pipeline delivered: 744/790 skills have real bodies; the 73-plugin scan pipeline ran on every plugin with a plausible verdict spread (29 safe / 33 review / 11 blocked) — this is not scaffolding.
- W2's F002 skills-tenancy fix is live where cited (`api/skills.py:160-182, 674, 795-812, 932-948` — residual map F002 FIXED).

**Concrete defects, most damaging first:**

1. **The flagship agent's prompt is corrupted by duplicate skills — live, today.** 205 active skill names are duplicated. `platform-management` exists five times global-active: four byte-identical builtin-core copies (ids 255-258) plus a divergent 70,784-char github import (id 249). Workspace Auto agent 340 is linked to platform-management **four times**. `SkillsSection` does no dedup by id or name (`sections/skills.py:48-100`): the first copy renders uncapped (~26.5 KB ≈ 6.6k tokens) and the other three fill the entire 5,000-token aux budget with *the same text* — roughly **5k tokens of pure duplication injected into every Auto turn** in the affected workspace, crowding out memory/graph/tool sections under the priority-trimmed budget. Root-cause chain, all verifiable: `seed_auto_agent` runs on hot request paths (`core/auth/hybrid.py:369`, `api/chat.py:112`, `api/workspaces.py:296`) across multiple workers; `_upsert_platform_management_skill` is query-then-insert with `.first()` and no unique constraint (`seed_auto_agent.py:81-133`); `_assign_skill_to_agent` is idempotent per `skill_id` but each worker's `.first()` can pick a *different* duplicate row (`seed_auto_agent.py:137-147`); `agent_skills` has no PK/unique (`core/models/core.py:29-32`); and the name-keyed loader (`skill_loader.py:889-892`) makes "which platform-management loads" plan-order luck between a 26 KB and a 70 KB body.

## D. Competitive teardown

**1. Anthropic Agent Skills — the open standard Automatos's format predates and now trails.**
Anthropic released Agent Skills as an open standard (2025-12-18); OpenAI, Google, GitHub and Cursor adopted it within weeks, making SKILL.md folders portable across Claude Code, Codex CLI, Gemini CLI, Copilot and Cursor ([agent-skills open-standard overview](https://www.agensi.io/learn/agent-skills-open-standard); [Anthropic engineering post](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)). The mechanics beat Automatos's implementation in three specific ways ([platform docs](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)): (a) **trigger-based activation** — L1 metadata (~100 tokens/skill) is all that's always loaded; the L2 body (<5k tokens) enters context *only when the task matches*, whereas Automatos injects every assigned skill's full body every turn (`sections/skills.py`) — the difference is exactly the 6-11k tokens/turn Auto pays; (b) **L3 as filesystem + execution** — bundled scripts run via bash and only their *output* enters context ("no practical limit on bundled content"), whereas Automatos's L3 is 34 skills with mostly-broken file paths and scripts that nothing executes; (c) **a versioned Skills API** (`/v1/skills`, workspace-wide sharing) as the management plane. Where Automatos is *ahead*: multi-tenant DB-backed skills with per-workspace forks, RBAC'd enablement, and an audited marketplace pipeline — the standard deliberately has no distribution/governance story (claude.ai custom skills are per-user, no org admin).

**2. OpenAI (Assistants API → Agents SDK / AgentKit) — a cautionary validation.**
OpenAI's hosted agent-object API is being removed on 2026-08-26 (Assistants → Responses/Conversations), and even AgentKit's visual Agent Builder + Evals got deprecation notices (2026-06-03, removal 2026-11-30) in favour of the code-first Agents SDK ([OpenAI deprecations](https://developers.openai.com/api/docs/deprecations); [AgentKit announcement](https://openai.com/index/introducing-agentkit/); [Azure migration thread](https://learn.microsoft.com/en-us/answers/questions/5571874/openai-assistants-api-will-be-deprecated-in-august)). Two lessons: Automatos's decision to own its agent-definition substrate (DB rows + its own executor) rather than lease a vendor's agent objects is *retroactively correct* — anyone who built a tenant plane on Assistants is now migrating; and the industry's convergence is "definitions as code/data + a thin runtime," which is what `AgentFactory` already is. OpenAI has nothing Automatos should adopt here.

**3. OpenClaw / ClawHub — the distribution benchmark and the supply-chain warning.**
OpenClaw's skill ecosystem hit 2,857 ClawHub skills within weeks; Koi Security's audit found **341 malicious** ones, Bitdefender measured ~17% malicious in the first weeks, and even after VirusTotal + ClawScan screening was added (Feb 2026, NVIDIA partnership June 1) evasive skills persisted — 22 MB README padding to defeat scanners, affiliate-link-manipulating "money-radar" ([Unit 42](https://unit42.paloaltonetworks.com/openclaw-ai-supply-chain-risk/); [eSecurity Planet](https://www.esecurityplanet.com/threats/hundreds-of-malicious-skills-found-in-openclaws-clawhub/); [Dark Reading](https://www.darkreading.com/cyber-risk/malicious-openclaw-skills-clawhub-threaten-ai-supply-chain)). Two-sided verdict: Automatos's *launch posture* is ahead — ClawHub shipped with no scanning; Automatos shipped a two-stage static+LLM pipeline that demonstrably ran on all 73 plugins with graduated verdicts. But OpenClaw's *distribution velocity* (thousands of community skills, instant install) is the capability bar for "agents gain skills without engineering time," and Automatos's 5 lifetime installs show the marketplace as a product hasn't started. The ClawHub incident also warns exactly where Automatos's scanner is weakest: regex-per-line static patterns are trivially evaded by obfuscation/padding (the scanner even skips the LLM stage on skill hot paths, `plugin_security_scanner.py:199`).

**4. CrewAI — the minimal-viable agent definition.**
CrewAI defines agents as `role` / `goal` / `backstory` YAML, decoupled from code, with tools and delegation rules ([CrewAI agents docs](https://docs.crewai.com/en/concepts/agents)). It is the industry's most-copied definition shape and proves how little schema a working agent needs. Automatos's model is strictly richer (org chart, marketplace, personas, voice, blueprints, RBAC) — an honest negative *for the competitor* — but CrewAI's simplicity highlights a real cost: Automatos spreads "who is this agent" across `configuration` JSON, `model_config` JSON, persona rows, custom prompts, blueprints and tags, and its own persona library loses 10:1 to bespoke prompts in production (199 vs 20), suggesting the definition UX, not the schema, is the bottleneck.

**Net position:** definition plane competitive-to-richer than anything listed; skill *loading mechanics* one generation behind the open standard (always-injected vs triggered, no script execution, broken L3); marketplace security posture ahead of ClawHub's launch, distribution/adoption far behind; execution spine solid and now converged — parity with the code-first SDKs for its purpose.

## E. Build / extend / adopt / replace — verdict

**EXTEND the agent plane; ADOPT the Agent Skills open standard as the skill format and loading model; KILL the dead third.**

- **Extend (keep building) the definition + execution plane.** Nothing external replaces a multi-tenant, DB-backed agent registry wired into board/Missions/channels/heartbeats: OpenAI's hosted equivalent is being sunset, CrewAI/LangGraph are libraries not tenant planes, and the factory is now the proven single spine. Building here is earned.
- **Adopt the Agent Skills standard** (spec at [agentskills.io](https://agentskills.io/home) / [Anthropic docs](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)) rather than continuing the in-house PRD-22 dialect. Automatos is ~90% format-compatible already (YAML `name`/`description` frontmatter, folder + SKILL.md, scripts dir — `skill_loader.py:133-177,794-854`); what to adopt is the *loading model*: L1-only always-loaded metadata, **trigger-based L2 activation** (a `load_skill` tool or model-driven read instead of `SkillsSection` injecting everything), and **L3 script execution** through the existing W14 workspace-worker sandbox instead of dead file paths. Payoff: the entire cross-vendor skill ecosystem (anthropics/skills and every standard-conformant catalog) becomes importable content, and Auto's per-turn skill cost drops from ~6-11k tokens to ~100/skill + on-demand. Integration shape: keep the DB as source of truth (the standard has no tenancy story — that's Automatos's genuine addition), make the loader emit/ingest spec-conformant folders, keep the scanner on the import path. Cost: format mapping + a loader-side activation tool + worker wiring — weeks, not months; no vendor fee (open spec).
- **Kill list** (per §2 nothing-is-sacred): `modules/agents/communication/inter_agent.py` (1,216 LOC, PRD-04, dead-chained but imported everywhere); `AgentService.create_agent` + the broken `create-specialized`/`batch-create` and 501-stub `test-capabilities`/`add-skills` endpoints; the placebo `POST /{id}/execute`; the `/active`+`/health` global-factory fiction; merge `api/agent_endpoints.py`'s five real routes (model-config/usage) into `api/agents.py` and delete the file. `AgentPerformanceService` folds or dies with the registry cleanup.
- **Do not adopt** an external marketplace/scanner vendor: the in-house two-stage scanner is architecturally right (ClawHub converged on the same shape post-incident), already ran in production, and the marketplace's problem is demand and content, not machinery.

## G. Quality metric

The module needs an **integrity + honesty + efficiency** triad, all cheaply computable from existing tables (feeds T3):

1. **Skill integrity score** — count of duplicate active `(name)` global skills (today **205**; target 0), duplicate agent↔skill links (today ≥4 on Auto; target 0), and skills whose `skill_source` fails to resolve to a provenance record (today: most rows). One SQL view, trended.
2. **Prompt-efficiency: skill tokens per turn** — from context assembly, tokens contributed by SkillsSection vs unique-content tokens (today on affected Auto turns: ~11.6k rendered vs ~6.6k unique → **~43% waste**; target <5% and, post-standard-adoption, an absolute drop to ~100 tokens/skill idle).
3. **Spine health per entry point** — success rate of `execute_with_prompt` split by caller (board/mission/scheduled/webhook/channel), from `agent_reports`/monitoring (today: only the Playbook lane writes durable per-agent stats, 59 agents, 0.40-0.86; entry-point split **unmeasured** — that gap is itself the finding).
4. **Surface honesty** — count of mounted-but-dead/fabricating endpoints on the agents surface (today ≥6; target 0, CI-guarded by a route-liveness test).
5. **Extensibility funnel** — marketplace installs/week (today ~0; 5 lifetime), scan verdict mix (29/33/11), skill activations once trigger-based loading exists.

## H. Cost note (informational)

- **Skills are the module's dominant recurring cost:** Auto's platform-management body ≈ 26.5 KB ≈ **6.6k tokens on every turn** (uncapped primary), plus up to 5k duplicated aux tokens in the corrupted state → ~11.6k tokens/turn; at Sonnet-class input pricing that is roughly $0.02-0.04 per turn *before the conversation itself*, doubled by the duplication bug, multiplied across every heartbeat/board/mission turn of every skill-bearing agent. Trigger-based loading (§E) converts this to ~100 tokens/skill idle.
- **Plugin LLM scan:** one Claude call per plugin (2,048-token cap, `PLUGIN_LLM_SCAN_MODEL`, `plugin_security_scanner.py:300-360`) — cents per plugin, one-time; 73 scans to date. Static stage is free.
- **Agent creation verification:** one live "Respond with OK" LLM ping per `create_agent` (`agent_factory.py:558-573`) — negligible, though it's currently unreachable via the broken endpoints.
- **Registry lookups:** `find_agents_with_tool` is O(N) DB queries per call at 237 agents (`agent_registry.py:239-257`) — compute, not tokens, but it's on Mission agent-matching paths.
