## Codebase Patterns
- ORM models import Base from `core.database.base` (separate file to avoid circular imports)
- All ORM models use `extend_existing=True` in `__table_args__` for safety
- Enums use `(str, Enum)` pattern for automatic string serialization
- Pydantic and SQLAlchemy models co-exist in the same module file under `core/models/`
- Register new model modules in `core/models/__init__.py` with wildcard imports
- Timestamps use `func.now()` from `sqlalchemy.sql` for server-side defaults
- JSON/flexible columns use `JSONB` from `sqlalchemy.dialects.postgresql`
- UUID columns use `PGUUID(as_uuid=True)` from `sqlalchemy.dialects.postgresql`
- Workspace isolation: most models include `workspace_id` FK to workspaces table
- Routing cache lives at `core/routing/cache.py` — use `RoutingCache` singleton for all routing cache operations
- Use `model_copy()` (Pydantic v2) when storing/returning models to avoid shared mutable state
- Routing engine lives at `core/routing/engine.py` — `UniversalRouter(db, cache)` is the single entry point for all routing
- `TriggerSubscription` links to `ComposioEntity.id`, not workspace_id directly — resolve workspace via `ComposioEntity`
- `IntentClassifier` categories: EMAIL, CALENDAR, CODE, COMMUNICATION, KNOWLEDGE, DATABASE, STORAGE, PROJECT_MANAGEMENT, ANALYTICS, AI, MEMORY
- Ingestors live at `core/routing/ingestors/` — each channel gets its own file inheriting `BaseIngestor`
- `RequestContext.user` is a `UserContext` dataclass (not a dict) — access fields via `.id`, `.email`, `.clerk_user_id`, `.role`
- DB sessions use `Depends(get_db)` in FastAPI endpoints — yields `Session` from `sqlalchemy.orm`
- LLM calls: use `create_llm_manager(service_name="orchestrator")` then `await manager.generate_response(messages)` — returns `LLMResponse` with `.content`, `.tool_calls`, `.usage`
- Agent model at `core/models/core.py` — filter by `workspace_id` + `status == "active"` for workspace agents
- Agent app assignments at `core/models/composio_cache.py` — `AgentAppAssignment` links `agent_id` to `app_name`
- Chat endpoint uses `stream_response_with_agent(agent_id=...)` for all agent-resolved requests — legacy `stream_response_aisdk` path removed
- Routing metadata exposed via `x-routing-*` response headers on chat streaming responses
- Background async dispatch: use `asyncio.create_task()` for fire-and-forget execution (pattern from `api/workflows.py`)
- `get_db_session()` is a sync `@contextmanager` — use `with`, not `async with`; auto-commits on exit
- Webhook ingestors selected by trigger_name prefix (e.g. `JIRA_` → `JiraTriggerIngestor`)
- Config centralization: `orchestrator/config.py` is the canonical place for `os.getenv()` — use `from config import config` in other modules
- Management scripts: add `sys.path.insert(0, str(Path(__file__).resolve().parents[1]))` at top, use `SessionLocal()` for DB sessions (not `get_db`), use `DEFAULT_TENANT_ID` for single-tenant mode
- Workflow recipes live at `modules/workflows/recipes/` — stateless classes with `async execute(envelope, db, workspace_id) -> Result` pattern
- `ComposioToolExecutor.execute()` returns `{"success": bool, "data": Any, "error": str}` — use admin pattern: `agent_id=0, skip_validation=True` for system-initiated actions
- `CodeGraphService.search_symbols(project_name, query, limit, workspace_id)` — `workspace_id` must be a string; results under `"results"` key
- Jira field values (issuetype, priority, project, reporter) are nested dicts — extract with `obj.get("name")` or `obj.get("key")`
