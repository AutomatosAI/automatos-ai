## Codebase Patterns
- ORM models in orchestrator/core/models/ use `extend_existing=True` on `__table_args__`
- Pydantic v2 patterns: use `model_config = ConfigDict(from_attributes=True)` instead of `class Config: orm_mode = True`
- Config singleton in orchestrator/config.py — only place where os.getenv() is called
- Auth via `get_request_context_hybrid` dependency — returns RequestContext with user, workspace_id, org_id
- Workspace isolation: most tables have workspace_id FK, filter queries by ctx.workspace_id
- Frontend API client in frontend/lib/api-client.ts with Clerk token auth
- Frontend uses Radix UI + TailwindCSS, component patterns in frontend/components/
- Agent model has marketplace fields: owner_type, owner_id, cloned_from_id, install_count, is_featured, is_approved
- Marketplace tabs exist: Agents, Tools, Recipes, LLMs in frontend/components/marketplace/
- Seeds in orchestrator/core/seeds/ — use upsert patterns for idempotency
- Agent creation wizard: 4 steps (Config → Model → Tools → Skills) in create-agent-modal.tsx
- Junction tables use composite PKs (see agent_skills association table pattern)
- FastAPI routers registered in orchestrator/main.py (lines 400-443)
- Existing S3 credential type defined but not yet implemented (core/credentials/types.py)
- Bedrock client uses boto3 with event system for API key injection
