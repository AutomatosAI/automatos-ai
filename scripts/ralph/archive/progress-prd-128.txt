- 2026-04-10: **US-003 done** — New `orchestrator/core/services/notification_dispatcher.py` implements `NotificationDispatcher(db, workspace_id)` with `async dispatch(event_type, title, message, link_type, link_id, agent_id, agent_name, status, user_id)`. `_get_preferences` returns a LIST of matching rows (no LIMIT) and applies user-override semantics per destination: user-specific rows shadow workspace defaults on the same destination while default-only destinations survive. Destinations: `silent` skipped; `in_app` inserts a `notifications` row via `db.execute` without committing; `telegram`/`slack`/`webhook` delegate to existing `send_workspace_notification(..., channel=destination)`; `channel` looks up the `channel_connections` row by id and dispatches via its platform. `_format_external_message` builds a concise status-icon + title + agent line + 200-char truncated message (ends with `…`) + TODO deep-link placeholder. No-preferences case falls back to a single in_app dispatch. Every destination branch is wrapped in try/except with `exc_info=True` so a delivery failure never raises out of the dispatcher. New unit tests in `orchestrator/tests/test_prd128_notification_dispatcher.py` (6 tests, all passing) cover: silent skip, in_app insert with no commit, in_app + telegram multi-destination fan-out, user override shadows workspace default on shared destination while unique default destinations survive, no-preferences in_app fallback, and `_format_external_message` truncation/icon behaviour. Tests stub `send_workspace_notification` with `AsyncMock` so no real network IO. Files touched: `orchestrator/core/services/notification_dispatcher.py` (new), `orchestrator/tests/test_prd128_notification_dispatcher.py` (new), `scripts/ralph/IMPLEMENTATION_PLAN.md`, `scripts/ralph/progress.txt`, `scripts/ralph/prd.json`.
